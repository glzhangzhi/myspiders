# 账单（finance）—— 约定

> 从 CLAUDE.md 拆出（2026-11）。改 `app/features/finance/` 前先读。
> 个人专属的商家规则在 .env 的 `FINANCE_PERSONAL_RULES`，不写进代码。

- **账单(finance)的三条铁律**。① **余额勾稽不平就拒绝入库**:`parse_and_classify` 返回 `ok=False` 时一笔都不写。N26 改版式会让正则**静默少抓一笔**,钱无声消失比崩溃难查得多;`reconcile()` 比对「期初 + 本期合计 = 期末」是唯一硬证明。② **重导 PDF 绝不覆盖人工标注**:`features/finance/repo.py` 的 `_USER_OWNED`(分类/标签/备注/确认状态…)走 `$setOnInsert`,`_MACHINE`(金额/日期/原始描述…)走 `$set`——**从不用 `model_dump()` 全量 `$set`**(菜谱 `prev_snapshot` 那个坑的同构形态)。`tests/test_finance_repo_fields.py` 用 ast 扫描守着,并强制模型新增字段必须显式选边。③ **Space 与主账户是两条腿**:一笔「主账户 → XJK Space」在 PDF 里是两条记录,统计非消费净额时**只认 `section=main`**,否则净额恒为 0、显示成「一分钱没存」。
- **账单的月份认账期,不认文件名**:`parse_text` 取 PDF 里的 `01.03.2026 bis 31.03.2026`。上传来的文件可以叫任何名字,而月份是交易 id 哈希的一部分——认文件名会让同一份对账单换个名字就生成另一批 id,重导变成「新增一份重复数据」。同理**序号必须进哈希**:3 月有两笔同日同额同商家的 GO ASIA,不带序号会被合成一条。
- **账单页面只关心支出**:收入来源单一稳定,收入/结余卡片与收支瀑布图已**刻意删除**。分布类图表(月度构成/类别占比/商家排行/日历)统一服从顶部**一个页面级开关**`fxOnlyVar()`,默认「只看可变支出」——固定支出占 73% 且每月雷打不动,含它时每张图第一眼都是「房租最大」,是无法据以行动的信息。作为开关依据的「固定 vs 可变」图**刻意不服从**该开关。切口径后务必横向核对:环形中心 / 统计卡 / 类别表合计 / 柱图合计 / 日历合计必须**全等**(`tests/test_finance_summary.py` 守着,那里踩过两次静默不一致)。
