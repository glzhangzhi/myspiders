# AI 小镇（town）—— 让酒馆角色卡自己过日子

从酒馆里勾几张（尽量单人的）角色卡，加上机主自己的人设（也由 AI 扮演），把他们
放进同一个小镇。点一次「下一天」，看他们按各自的设定自己发生故事。机主原话：

> 我最感兴趣的，就是这种「如果 AI 自己来玩酒馆，这些人物会发生什么故事」的效果。

仪表盘入口：侧栏「生活 → AI 小镇」，或 `/dashboard/town`。

---

## 一步 = 一天（机主定的流程，别改成实时模拟）

参考过 a16z-infra/ai-town：那边是 60fps 引擎 + 寻路 + 两两逐句对话，社交决策
（找谁聊、接不接受）全是规则加随机数。这里刻意做成回合制，三段：

| 段 | 调用 | 输入 | 输出 |
|---|---|---|---|
| 早上 | 每人 1 次 | 自己的设定 + 自己的日记 + 地点列表 | 去哪、内心想法、打算 |
| 白天 | 每个**有人的**地点 1 次 | 在场者的设定 + 各自的想法与日记 | 一场戏（小说体）+ 这个地点新确立的事实 |
| 晚上 | 每人 1 次 | 自己的设定 + 自己日记 + 自己在场那场戏 | 第一人称日记、心情、目标、对别人的印象 |

- **一个人的地点也演**（机主定）：独处也有戏，而且很便宜。
- **穿越开局**（机主定）：第 1 天每个人在陌生屋子里醒来，记得原作的一切，见不到原作里的任何人。
  卡里的 `{{user}}` 换成「原作主角」而**不是**机主的名字 —— 否则每张卡都会以为和他早有原作里的关系。
- **我 = 张超（「不打折」那份人设，2026-11 机主定）**，也由 AI 扮演，机主纯旁观。
  人设只写内核不写外在身份，所以入住时自动加一段「小镇补充」（普通成年人、现代都市来的），面板可改。

## 记忆 = 日记

日记就是居民的全部持久记忆，之后每次调用**全部带上、不压缩**（机主定）。
`town_memory_days_cap`（默认 60）只是保险丝：超过就只带最近 N 篇并在提示词里写明「更早的略」。

居民的心情/目标/印象**不单独存**，一律取最新一篇日记；地点上的事实取已完成各天场景的
`place_facts`。所以「回退到第 N 天」只需删掉之后的 days 和 memories，不会有状态错位。

## 设定：原样喂，不压缩（机主定）

- 世界书优先读卡上 `extensions.world` 链接的**独立文件**（酒馆运行时用的是它），
  文件不在才回落到卡内嵌的 `character_book`。`charLore.extraBooks`（多是 Memory_Context
  聊天记忆）**刻意不读**：小镇开局只有人物本身。
- **常驻（蓝灯）**条目每次原样带上；**关键词（绿灯）**按当次上下文匹配激活
  （二级关键词逻辑、2 轮递归、正则键；**不做概率**，同一输入得到同一份设定）。
- **机关条目自动排除**：MVU 变量、EJS、状态栏、输出格式、HTML。实测 389 张卡里 249 张
  带这类条目，漏进去模型会开始输出状态栏。判据是启发式的，**一定误判**，所以面板里
  每条都能手动开/关（`overrides`），排除理由逐条显示。
- 居民入住时设定**快照进库**，酒馆里改卡不影响已经跑起来的小镇；要跟上走「从酒馆重新读取」
  （保留手动开关、**不改名字** —— 日记和印象里都是旧名字）。

实测 389 张卡渲染后的固定设定块：中位 1.0 万字、p90 2.6 万字、最大 8.8 万字。

## 小镇设定（全镇客观事实）

几场戏是**并行**生成的、互相看不见。「镇上有没有别人」这种全局事实不写死，就会
一场说空无一人、另一场说街上人来人往 —— 第一版实测撞到：张超在第 3 天跟踪了
一个模型凭空编出的路人走进雾里。现在每个镇有一段 `lore`（面板可改），默认是
「除了居民没有任何人、设施开着但无人经营、外围浓雾走进去会回到镇上」，
场景提示词里也明令「不许凭空添加有台词或行动的人物」。之前场景确立的地点事实与小镇设定冲突时，以小镇设定为准。

## 前缀缓存：提示词的拼装顺序是为它排的

    system = 通用总则 + 小镇设定 + 人物设定块（按居民序号）   ← 恒定
    user   = 日期、地点、日记、关键词条目、任务要求             ← 每次不同

同一个人一天被调用 3 次，设定块又是最大的一块，放在最前且逐字不变时后两次几乎全按
命中价计费（未命中价的 1/50）。`tests/test_town.py` 钉着「同一人两次调用 system 逐字相同」
「关键词条目不进 system」。**往 system 里加任何会变的东西（日期、记忆）都会让缓存整段失效，不报错，只是变贵。**

## 成本与用时（实测，3 位居民）

| | 调用 | 花费 | 用时 | 缓存命中 |
|---|---|---|---|---|
| 第 1 天 | 8 | ¥0.098 | 41 秒 | 46% |
| 第 3 天 | 8 | ¥0.105 | 约 60 秒 | 71% |

模型 `deepseek-flash`（思考模式开），价格按**高峰价**估（`town_price_*`，宁可显示偏高）。
居民多、设定长的卡会线性变贵：5 人 × 2 万字设定大约 ¥0.3–0.5/天。

## 断点续跑

每完成一个调用立刻落库（`plans.<rid>`、`scenes.<place_id>`、`town_memories`）。
中途失败/服务重启后再点，按钮变成「继续第 N 天」，只补缺的调用。
运行状态只在进程内：库里 `status=running` 但进程里没有任务 = 被重启打断，读的时候报 `interrupted`。
同一个镇同时只能跑一天（409）。
